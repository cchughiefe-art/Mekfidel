## Current verification

The local production build, TypeScript checks and lint pass. The latest completed suite has 18 passing tests. Database tests use an isolated PostgreSQL instance, not business data. The migration and application changes have not yet been verified together on Vercel. This tracker distinguishes implemented code from live verification.

External setup remains: a Groq API key is not configured, outbound order notifications are not connected, and the business must confirm its payment/delivery/returns terms. Provider free quotas are account-specific. Real Android device testing is still needed.

## Additional live security checks

Supabase's security advisor also identified mutable search paths on legacy trigger functions and unnecessary client execution permissions on internal trigger functions. The prepared migration fixes those paths and revokes direct client execution. The existing `is_cms_admin` role predicate has a fixed search path and intentionally remains executable for RLS; its only output is a boolean for the caller's own role.

Leaked-password protection is currently disabled in Supabase Auth. Review availability and configuration in the account before enabling it: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection . Function-search-path remediation: https://supabase.com/docs/guides/database/database-linter?lint=0011_function_search_path_mutable . The migrations are applied live. Remaining advisor notices include intentional role predicates, view-count RPCs and private server-only tables, plus disabled leaked-password protection.
